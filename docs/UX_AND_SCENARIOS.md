# Visual Design, Portals and Safe Demo Scenarios

## Interface language
Premium dark engineering dashboard; restrained red accents for Red/Attacker, teal for Blue/Defence. Clear 'VIRTUAL SCENARIO' and 'SIMULATED SENSOR' labels. No operational battlefield branding/claims. Desktop/projector readable with usable mobile fallback.

## Red Portal panels
World viewer with orbit/zoom and click placement; object palette: surface-visible, partially obscured, buried (all synthetic), decoy. Selected object X/Z coordinate editor, move/delete, list/count, scenario mode/lock, join code and public defence link, private attacker control access, optional drone tracking, event log.

## Blue Portal panels
World and 3D drone viewer, manual waypoint or grid rectangle planner, route preview, Basic/Advanced and Narrow/Standard/Wide settings, camera toggle (Overview/Follow/Top-Down), speed 1x/2x/4x and flight commands, virtual telemetry, candidate detection/map panel, final truth comparison and printable report.

## Prepared purely fictional scenarios (illustrative; update for actual world bounds)
ALPHA — Basic/Challenge: on a 200x200 virtual world, hazards around (30,40), (75,80), (120,105), (170,160) and decoy (60,130). Use a mission that deliberately leaves one hazard unscanned. Report only engine-calculated outcome.
BRAVO — Advanced/Challenge: several hazard categories, decoys, fixed seed, illustrate simulated miss/false alarm only if actually generated by the algorithm.
CHARLIE — Live: start with one hazard, add/move another during flight; preserve event-time reasoning and no retroactive detection.

## Reliability principles
The defender must never see hidden placements before observations; no pre-scripted universal mine pins. Invalid route, coordinate errors or offline disconnection receive clear actionable messages. Object placement click must not be confused with orbit drag. Ensure map legends separate route, surveyed, candidate, revealed truth and not-scanned.
