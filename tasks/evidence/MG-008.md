## Delivered
- `shared/sensor.ts` is the single source for sensor settings: radii 6/10/16, Advanced thresholds .90/.70/.50/.20, `SENSOR_EPSILON = 1e-6`, coverage resolution 1, the `PublicCandidate` and `CoverageEstimate` types. It also has:
  - `firstEntry`: the exact first-entry solution on a segment;
  - `drawFromDigest` and `drawKey`: a SHA-256 hash, keyed on seed, mission ID, object ID and `sim-v1`, converted to a 53-bit number between 0 and 1;
  - `decide`: the Basic/Advanced decision table.
- `server/src/mission/sensor.ts`:
  - The pure `sweep()` runs chronologically over the flown sub-segments, clips each placement to its active span, and orders results deterministically.
  - `CoverageGrid` is a 1-unit cell union, clipped to the world, with a grid-coverage percentage.
  - `SensorEngine` does the following:
    - private `sensor_decisions` and public `candidates` tables;
    - each decision and its candidate are written in one transaction, before broadcast;
    - one decision per (mission, object), with no re-roll after a restart;
    - Live edit timing via `RoomStore.onObjectChange`, which carries the mission sim time;
    - review updates;
    - coverage is rebuilt after a restart.
- The engine, routes and realtime layer gain:
  - `MissionSnapshot.candidates` and `MissionTelemetry.coverage`;
  - `GET /mission/observations` and `PATCH /mission/observations/:id/review`;
  - the `observation:created` socket event;
  - public mission data also goes to the Red channel, for drone tracking.
- Client:
  - `lib/useMissionState.ts` merges snapshots, telemetry and candidates, keyed by candidate ID so nothing duplicates.
  - `blue/MissionLayer.tsx` adds the live footprint (a translucent disc and ring draped over the terrain, with radius from `FOOTPRINT_RADIUS`), the swept region (a 2r ribbon per leg plus discs at passed waypoints, drawn only along the flown path), and candidate pins C1, C2… (rose octahedra on stems with pulsing rings; click to select). END waypoints are now violet so they don't look like candidates.
  - `blue/BluePanels.tsx` adds the `Findings` list (number, X/Z, sim time, sensor, review toggle), the detail note "Simulated candidate detected … not a confirmed mine", the synthetic disclaimer, and estimated coverage in telemetry.
  - `pages/DefencePortal.tsx` wires these in.
  - `pages/AttackerPortal.tsx` adds the "Show defence drone, footprint and public candidates" toggle for Red tracking.
- Tests:
  - `server/test/sensor.test.ts` (24 tests);
  - `tests/e2e/sensor.e2e.ts` (one browser journey);
  - MG-007 tests updated where MG-008 legitimately changes behaviour (see below);
  - `test:e2e` now runs the browser files one at a time.
- Docs: API_CONTRACT "Implemented (MG-008)", an ARCHITECTURE "Virtual sensor" section, and README updates.

## Changes to earlier tests (and why)
- MG-007 privacy tests (M29, in the backend and browser) placed a "hidden" BURIED hazard at (81.9, 21.3), which is 2.3 units from the DEMO A route. Before MG-008 nothing sensed it. Now the Basic sensor would correctly publish it as a candidate (contract rule 10 allows the candidate's location to be disclosed). It was moved to (181.9, 21.3), off the route, so those tests still check that unscanned data stays private. The scanned case is covered by D02, D18 and D19.
- The MG-007 browser test now expects "No candidates yet" instead of the old placeholder text.

## Defects found and fixed during testing
1. A browser-test timeout once five e2e files ran in parallel. Five headless Edge instances doing software WebGL starved the CPU, while the test passed alone. Fixed in the harness: `test:e2e` uses `--test-concurrency=1`, and two consecutive full runs were 5/5. The app itself was not involved.
2. Hand-calculated entry-time assertions were too strict (1e-9) for the documented 1e-6 radius tolerance, which shifts entry about 1e-7 s earlier. Analytic comparisons now allow 1e-5 s; run-to-run comparisons stay at 1e-9.

## Known limitations
- Exact sub-tick Live timing is kept in memory for the tick in which an edit happens. If the server dies inside that same 100 ms window, the mission comes back paused, and edits made while paused are evaluated on resume (D28 rule). There's no catch-up and no duplicates, but that one partial tick isn't replayed.
- One decision per object per mission: an object missed by Advanced and then moved isn't re-tried (contract simplification; to be stated in the MG-010 report).
- Coverage is an estimate on a 1-unit cell grid (cell centres), shown as "Estimated virtual coverage". The swept-region drawing approximates on hills but matches in X/Z.
- Candidate positions equal the object positions; there is no localisation noise (allowed for V0.1 by rule 10).
- Results, metrics, truth reveal and report export are not implemented (MG-010).
