## Delivered
- `shared/sensor.ts`: the one definition of sensor modes (BASIC/ADVANCED), footprint radii (NARROW 6, STANDARD 10, WIDE 16), `maxGapFreeSpacing = 2r`, and the algorithm version `sim-v1`.
- `shared/mission.ts`:
  - Plan, telemetry, snapshot and command types, plus `buildPlan`.
  - `validateManual`: 2–50 points, validate-before-round, no zero-length legs.
  - `generateGrid`: deterministic serpentine, both edges included, auto/explicit orientation, spacing at most the requested value, up to 60 lanes, gap flag.
  - `poseAt` and `flownSubsegments`, which split each tick at every crossed waypoint for MG-008 sweeps.
  - Constants: altitude 12 above the terrain, base speed 8 units per simulated second.
- `server/src/mission/engine.ts`: the server-authoritative engine.
  - SQLite tables `mission_plans` and `missions`, a 100 ms tick, and the clock rule `simTime += realΔ×speed`.
  - Exact arrival at the end; commands START, PAUSE, RESUME, STOP, SET_SPEED and NEW_MISSION, each checked against the state machine.
  - One mission per room, plan-revision checks, and `sweepHook`.
  - Fail-closed restart (a running mission comes back paused). Live audit events get the mission's sim time.
- `server/src/mission/routes.ts`: `GET /mission`, `POST /mission/plan` and `POST /mission/command`, room-scoped.
- `server/src/app.ts` and `rooms/realtime.ts`: Blue sockets get `mission:snapshot` on join, and `mission:telemetry` about 10 times a second. A Red lock or mode change re-pushes Blue's mission snapshot.
- Client:
  - `world/CameraRig.tsx`: Overview, Follow and Top-Down with smooth transitions and Reset view. It records the camera pose in `data-camera` for tests.
  - `world/WorldView.tsx`: gains `cameraMode`, `followTarget` and `cameraResetKey` props. Red is unchanged and defaults to Overview.
  - `blue/MissionLayer.tsx`: the dashed draft preview and solid confirmed route, both draped over the terrain; numbered waypoints with START/END; the planned grid rectangle; the drone model with spinning rotors, a nose marker for heading and a ground shadow; and the flown-path trail. The drone eases along the route by distance, so it never cuts a corner.
  - `blue/BluePanels.tsx`: the manual editor (add, edit, reorder, remove, clear), grid editor, sensor config, flight controls and telemetry.
  - `pages/DefencePortal.tsx`:
    - Planner tabs, click-to-add-waypoint and pick-corners modes (with "Exit planning mode"), and an instant local preview built by the same `buildPlan` the server runs.
    - Confirm plan, with confirmed / stale / flying states, then Start, Pause/Resume, Stop, New mission, and 1×/2×/4×.
    - Telemetry, the findings placeholder, and the camera selector.
    - After a refresh, the draft is reloaded from the server's confirmed plan.
- Tests: `server/test/mission.test.ts` (19 tests, fake clock with manual ticks) and `tests/e2e/mission.e2e.ts` (one full browser journey).
- Docs: API_CONTRACT "Implemented (MG-007)", an ARCHITECTURE mission engine section, and README updates.

## Defects found and fixed during testing
1. **Blue's Start stayed blocked after Red locked**, because Blue's mission snapshot was not re-pushed on room changes. Fixed: every room change now also pushes `mission:snapshot` to the public channel. The browser test checks that Start enables without a refresh.
2. **The planner looked empty after a refresh** ("Draft changed: confirm again" while flying), because the local draft is browser-only. Fixed: the draft is reloaded from the server's confirmed plan after a refresh, and while flying the status reads "Flying the confirmed plan". The browser test checks for 5 rows and the confirmed state after reload.
3. The Reset view button covered the X 200 corner label; it now sits on the camera selector's row.
4. Test-only issues that weren't application bugs:
   - the sweep collector also picked up other rooms' missions;
   - a grid-end expectation was wrong (the serpentine ends at X 20);
   - at 4× the route finished during the camera checks;
   - coordinate substrings matched long telemetry floats such as `96.79…`. Coordinates are now matched as whole numbers only, and the helper was checked on positive and negative cases;
   - a TypeScript narrowing issue in the engine's `tickAll`.

## Known limitations
- The MG-008 interface is ready but not implemented: `MissionEngine.sweepHook` receives ordered `FlownSubsegment`s with sim times; mission `seed` is generated and stored; `sensorMode` / `footprintProfile` are frozen in each mission's plan.
- Any guest with the room code can control the mission. There's no single-controller lock, and commands are serialised on the server. This is documented.
- Routes are straight lines between waypoints at 12 units above the terrain. Scenery is not an obstacle.
- Speed changes take effect from the next tick (100 ms).
- If the event loop stalls for more than 2 s (for example, laptop sleep), at most 2 s of flight is simulated per tick.
- The WebGL tests use software rendering; GPU frame rate wasn't measured. Two physical devices and phone touch are MG-011.
