## Known limitations — not misrepresented as passed

1. Report export is **standalone HTML with browser Print / Save as PDF**. It is not a direct server-generated binary PDF download. Chromium PDF generation works in headless E2E, but user printer interaction was not manually tested.
2. **Visual A4 pagination, real printer/grayscale and projector readability were not manually inspected by a human**. Do this during MG-013 final release QA. Automated PDF signature/size checks are not visual inspection.
3. Missions created before the MG-010 baseline mechanism lack full historical snapshots and deliberately fail closed with REPORT_HISTORY_UNAVAILABLE instead of reporting fabricated results.
4. Documented V0.1 Live limitation: one sensor decision per stable object per mission, even after moving or reclassifying.
5. Coverage is an approximate 1-virtual-unit grid union over actually flown path, not a safety guarantee; no localization noise in candidate coordinates.
6. All hazard detection is **fictional and synthetic**; no actual landmine or buried-mine sensing, ML accuracy or field clearance.
7. Physical two-device LAN/online/phone testing is MG-011 (Rahil), not claimed for MG-010.
8. During npm ci the runner noted 2 moderate dependency advisories. A disruptive automatic audit fix was not attempted; review them before release in MG-013.
