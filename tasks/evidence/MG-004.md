## Delivered
- `shared/scenario.ts`: categories (3 hazard and 3 decoy subtypes), kind/subtype validation, and coordinate normalisation, which rejects bad values **before** rounding and then rounds to 0.1. Also the error codes, snapshot types, the edit matrix `canEditObjects`, and `MAX_ACTIVE_OBJECTS = 100`.
- `server/src/rooms/store.ts`: SQLite store with three tables, `rooms`, `objects` (soft delete) and `audit` (private before/after records).
  - The server generates all IDs, timestamps and revisions.
  - Each change and its audit record are written in one transaction.
  - The attacker token is 32 random bytes; only its SHA-256 hash is stored, and checks use a constant-time comparison.
  - `setState` is the hook the mission engine (MG-007) will use.
- `server/src/rooms/routes.ts`: room creation, the public snapshot, and the attacker-only object routes (create, edit, delete) plus mode and lock routes, all requiring the token as a Bearer header.
- `server/src/rooms/realtime.ts`: `room:join` with an ack. Red and Blue sockets use separate channels (`red:<id>` and `pub:<id>`), and role-filtered snapshots are pushed after every change.
- `server/src/app.ts`: wires the store, routes and sockets together; returns JSON errors for malformed request bodies; DB path from `MINEGUARD_DB`, defaulting to the gitignored `data/mineguard.sqlite`.
- Client:
  - `pages/AttackerPortal.tsx` and `red/RedPanels.tsx`: Create Room, then the room code, the public defender link and the masked private link, each with a copy button and an insecure-context fallback.
  - Mode switch (Challenge/Live), Lock Scenario with a visible LOCKED badge, and the revision number.
  - A 6-category palette, click-to-place mode, and X/Z coordinate entry.
  - The selected-object editor (category, X, Z, save, two-step delete), the object list (type, X, Z, ID, revision) and the private history.
  - Error banner and live/offline indicator.
  - `world/ObjectMarkers.tsx`: a distinct Red-only 3D marker for each subtype, a selection ring, and a ghost marker while the server confirms.
  - `world/WorldView.tsx`: gains `onPick`, `renderScene` and `overlay` props. MG-002 behaviour is unchanged, including hover, orbit, the 4 px drag rule and corner labels.
  - `lib/useRoomSocket.ts`: joins the room, re-joins after every reconnect, and ignores stale snapshots.
  - `pages/DefencePortal.tsx`: join by code or `/blue/CODE` link; shows room metadata only.
- Tests: `server/test/rooms.test.ts` (19 backend tests) and `tests/e2e/rooms.e2e.ts` (one full browser journey). `tests/fixtures/scenario-alpha.json` holds the synthetic ALPHA fixture.
- Docs: API_CONTRACT "Implemented (MG-004)" section (routes, errors, socket events, edit matrix), an ARCHITECTURE persistence section, and README updates (Node 22.13+, DB location, routes, layout).

## Defects found and fixed during testing
1. An HTTP server can emit `close` twice, which closed SQLite twice and threw "database is not open" during test teardown. Fixed: `RoomStore.close()` is now safe to call more than once.
2. A test false positive: R11's first version matched "31.7" inside a `server:hello` timestamp, and its first patch failed to apply, so the public `/api/world` terrain was still counted as Blue scenario traffic. Fixed by making the test check real object fields (IDs, kinds, `"x":` keys) and by excluding the static terrain and the time-only hello message. The application had no leak.
3. Usability: markers were too small to see at the default overview zoom on a projector. They're now drawn at 2× size, and the history timestamp column no longer wraps. Screenshots were re-taken.

Screenshots (headless Edge, full page): `tasks/evidence/screenshots/MG-004-red.png` (5 objects, LOCKED, private history) and `tasks/evidence/screenshots/MG-004-blue.png` (same world, LOCKED, revision 10, no markers).

## Deferred / known limitations
- **R16 runtime:** no mission engine exists yet, so RUNNING/PAUSED can only be reached through `RoomStore.setState` in tests. Live edits during an actual flight, recording `missionSimTime` from a real mission clock, and no-retroactive-detection belong to MG-007/MG-008.
- Optional Red view of the drone (decision 14) belongs to MG-007/MG-008.
- `scenarioRevision` is visible to Blue as the contract allows. It shows that Red changed something, but not what, where or how many objects exist.
- The private link is in Red's URL fragment and address bar. The UI warns not to project it. Plain-HTTP LAN use is a classroom fallback only; use the HTTPS tunnel (MG-011) on untrusted networks.
- `node:sqlite` is experimental in Node 24 and prints a warning at startup. It needs Node 22.13 or later (`engines` updated).
- Tested on one laptop with separate browser contexts. Two physical devices and phone touch are MG-011.
- No undo after a confirmed delete; the two-step confirmation is the safeguard the contract allows.
- Bundle size is 1.09 MB (308 kB gzip).
